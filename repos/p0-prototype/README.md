# 坐姿提醒 · P0 原型

在**本机**本地跑通「采集 → 姿态推理 → 判定 → 语音提醒」全链路。
推理全程本地，不依赖任何远程算力。

> 📖 **纯侧面方案（当前采用）见 [`../../docs/03-side-only-plan.md`](../../docs/03-side-only-plan.md)**

## 两种模式

| `演示模式.bat` | 不接摄像头，循环展示「坐得好／提醒／看不到人」三种状态，**语音提醒也会播** |

> 演示模式**会出声**——它是用来预览真实体验的，不出声就没法完成报告 §7
> 「让孩子听一遍，确认不刺耳、不反感」这一步。
> 若点了 `演示模式.bat` 却没声音：先看主界面「声音」按钮显示的是"开"还是"关"，
> 再看系统音量。也可以在「家长设置 → 提醒与声音」里逐个**试听**语音片段。

### 窗口尺寸会按屏幕自动收敛（HDPI 注意）

实测这台笔记本：**1920×1080 物理屏开 150% 缩放 → Qt 的逻辑桌面只有 1280×720，
可用高度仅 680**。窗口尺寸写死会直接超出屏幕（标题栏被顶出、底部按钮被任务栏压住）。

> 📌 **本机实测（2026-09-26，`--screen`）**：逻辑桌面 **1920×1080**、可用区域 **1920×1032**、
> 缩放 **2.00x** —— 高度充足，不会出现上面那种被压住的情况。下面这套自适应逻辑仍然保留，
> 它是给"换到更小/更缩放的屏幕"兜底的。

所以初始尺寸按 `availableGeometry()` 收敛，并用屏幕可用区域居中；最小尺寸设为 700×500。
如果你在别的机器上看到窗口装不下，先跑这条查真实屏幕参数：

```bash
envs\posture\Scripts\python.exe posture_app.py --screen
```

它会打印「逻辑几何 / 可用区域 / 缩放」三项，一眼能看出是不是缩放问题。

⚠️ **别用 `--selftest` 查屏幕参数** —— 它强制走离屏（offscreen）平台，
报的是 800×800 的假数据，会把人带偏。`--selftest` 是用来验界面代码的，不是验屏幕的。


界面设计（依据报告 §8 的儿童场景研究）：

| 原则 | 做法 |
|---|---|
| 零操作启动 | 双击即开始监测，孩子不需要按任何按钮 |
| 先看脸色再看字 | 状态用大色块 + **手绘表情**（Canvas 画，不用 emoji，避免字体差异变方块） |
| **不用红色** | 警示用暖橙。红 = 惩罚感，会让孩子想关掉程序 |
| 正向激励 | 坐得好时绿色大字「坐得真棒！」，"坐得好的时间／良好率／连续良好"放在最显眼处 |
| **空格键暂停/继续** | 不用去点按钮。⚠️ 底部按钮设成不可获得焦点 —— Qt 默认把空格当"点击"焦点按钮，不设的话空格会被抢走 |
| 设置隔离 | 阈值、标定、提醒节奏全在「家长设置」里，孩子界面看不到 |

技术结构：界面（`posture_app.py`）**只画界面**，采集+推理跑在 `posture_engine.py` 的独立线程里，
两者靠快照通信——推理放主线程会让界面在最关键时刻卡死。

### 阈值标定：靠「审核判定」页收数据，不要靠录视频

任务书 §6 原本写的是「录 15~20 分钟视频 → 人工逐帧标注 → 扫阈值」。**这条路走不通**：
逐帧标注 15 分钟视频的成本太高，家长不会做，而「误报率 < 10%」这个验收指标
就永远算不出来。

改成**在使用中顺手标注**：

1. 引擎在**每次提醒时**自动存一张现场图（含当时的指标与基线）
2. 另外按固定间隔（默认 3 分钟）存一张「判为良好」的抽样
3. 家长在「家长设置 → 审核判定」里逐条点「对／不对」
4. 「审核判定」页底部直接用你已审核的样本**反推建议阈值**

⚠️ **能力边界（界面里也写着）**：

| | 说明 |
|---|---|
| ✅ 能发现**误报** | 判「歪了」其实坐得好 |
| ❌ 发现不了**漏报** | 漏报时程序压根没存图 —— 所以才要存那些「判为良好」的抽样来查漏 |

还有一条**归因规则**：一条样本只用来调**它自己触发的那个指标**。
家长标「确实歪了」可能是因为塌腰，而那一帧的 `neck_angle` 可能很低 ——
拿它去压 `neck_angle` 的阈值就是错的。

**这套数据只能用来调阈值，不能用来重训练模型**（两者完全不同）：

| | 调阈值 | 重训练模型 |
|---|---|---|
| 改什么 | 判定规则（12° → 16°） | 关键点模型本身 |
| 数据量 | 几十条 | 几百~几千张 |
| 标签 | 「对／不对」决策标签 | **每个关键点的 (x,y) 坐标** |
| 人工 | 每条 2 秒 | 每张 1~2 分钟 |
| 跑在哪 | 本机，秒级 | 训练平台，小时级 |

存的是 480px 缩略图，且只有决策标签 —— 没有关键点真值，**不能用于训练**。
（`review_keep_fullres` 控制是否为「提醒现场」另存一张**原图**。
2026-09-26 按用户的"处处用最高清"**改成默认开启**：摄像头已是 1080p，
留一张原图等于把"以后还能不能做模型微调"这个选项保住 —— 那些帧是回不来的。
代价是原图也计入 `review_max_files`，可留存的条数会变少；想省空间就在界面上关掉。）

**隐私**：全部存本机 `review\` 目录、不上传；上限默认 300 条（超出自动删最旧的，
且优先删未审核的，保证标注不丢）；「审核判定」页有**一键清空**。

### 摆好机位后，先用「家长设置 > 机位检查」确认


定位问题的失败方式是**静默的**：把摄像头正对孩子，程序不报错、不崩溃，
但**永远不提醒**——因为正面视角下同侧的耳和肩几乎在一条竖直线上，
前后关系被压扁，`neck_angle` 恒接近 0。

所以「机位检查」页给出量化确认：点「开始观察」，**让孩子往前伸一下头再坐回去**，
看「颈部前倾角摆幅」涨到多少：

| 摆幅 | 判定 |
|---|---|
| ≥ 10° | ✅ 机位没问题，前后关系确实测得到 |
| 5~10° | ⚠️ 勉强可用，建议再往侧面转一点 |
| < 5° | ❌ 摄像头太正对孩子了，转到 80~90° 正侧 |

两个设计选择，都不是随手定的：

1. **判据用「摆幅」而不是「当前值」** —— 家长多半在孩子正常坐着时打开这一页，
   当前值天然正常，拿它判会误报"机位不对"。
2. **判据用「摆幅」而不是「相对基线的差值」** —— 摆幅不需要基线，
   所以**不用等标定跑完就能验机位**（标定要 10 秒且需要孩子坐正，
   先验机位再标定，顺序更顺）。

## 参数

| 参数 | 用途 |
|---|---|
| `--list-cameras` | 列出可用摄像头（**排查第一步**） |
| `--bench --bench-frames 100` | 性能自测（**需真人入画**） |
| `--side-only` | **纯侧面单路模式**（纸笔作业推荐） |
| `--camera N` | 主路索引；`--side-only` 时指侧面机位 |
| `--camera2 N` | 第二路（侧面）索引；给了就启用双机位。与 `--side-only` 互斥 |
| `--side-yaw 90` | 侧向机位偏航角（度）：0=正对，90=正侧。**建议 80~90，不要用 45** |
| `--backend MSMF` | 强制指定采集后端（默认 DSHOW→MSMF→ANY 依次试） |
| `--calib 10` | 标定时长（秒） |
| `--model pose_landmarker_full.task` | 换更高精度档位（一般不需要） |
| `--no-window` | 不开预览窗（长期挂机） |
| **`--video 录像.mp4`** | **离线复现判定**：不接摄像头，把一段录像跑完整条判定链并输出逐条时间线（配 `--calib` 用录像前段标定，`--calib 0` 则用现有 baseline.json）。**跑得比真实播放快，且结果可复现** |

## 指标一览

### 侧面（像素空间算角度，已做宽高比 + 偏航校正）

| 指标 | 含义 | 阈值（相对基线） |
|---|---|---|
| `neck_angle` | 肩→耳 与竖直方向夹角 | +12° → **头前倾** |
| `trunk_angle` | 髋→肩 与竖直方向夹角（需髋可见） | +8° → **塌腰** |
| `sh_ear_len` | 肩→耳 直线距离 | 收缩 12% → **低头** |

### 正面（按肩宽归一化）

| 指标 | 含义 | 阈值（相对基线） |
|---|---|---|
| `head_drop` | 耳-肩垂直距离 / 肩宽 | 收缩 10% → 低头 |
| `head_tilt` | 双耳高度差 / 肩宽 | +0.06 → 歪头 |
| `shoulder` | 双肩高度差 / 肩宽 | +0.05 → 歪肩 |
| `span` | 肩宽绝对值 | 膨胀 15% → 太近 |

**为什么正面能忽略宽高比、侧面不能**
正面所有指标都**除以肩宽**，宽高比的影响在「当前值 / 基线」这一步自然抵消；
侧面左右肩在画面里几乎重合，**肩宽不可用**，只能靠角度——角度对宽高比是敏感的，
不校正就会被压扁（16:9 下少 44%）。

## 能测什么 / 不能测什么

| 坐姿问题 | 正面 | 侧面 | 纯侧面模式 |
|---|---|---|---|
| 头前倾（CVA 颅椎角） | ❌ | ✅ | ✅ |
| 塌腰 | ✅ | ✅ | ✅（需髋可见） |
| 低头 / 趴桌 | ✅ | ✅ | ✅ |
| 歪头 / 歪肩 | ✅ | ❌ | ❌ 已放弃 |
| 距离过近 | ✅ | ❌ | ❌ 纸笔场景不适用 |
| 含胸驼背（两路互证） | ❌ | ❌ | ❌ 需双机位 |

**为什么正面测不出驼背**：正面视角下「前后方向」被压扁成几乎没有信息，
这不是模型好坏问题，是几何决定的。必须靠侧面机位。

## 语音提醒

预生成的音频放 `voice/`，按问题命名，**缺失时自动退回系统提示音**：

```
voice\头前倾.wav  voice\塌腰.wav  voice\低头.wav     <- 纯侧面模式用这三个
voice\歪头.wav  voice\歪肩.wav  voice\太近.wav  voice\含胸驼背.wav   <- 双机位模式额外需要
```

**文件优先级：`<问题名>.wav` > `<问题名>.mp3`。** 原因见下。

### 为什么最终存 wav

| | wav（winsound 播） | mp3（只能 MCI 播） |
|---|---|---|
| 播放调用 | `PlaySound(SND_ASYNC)`，**真异步、无设备开关开销** | `mciSendString` 的 open/close 是**阻塞**调用 |
| 并发 | 天然安全 | 别名全局唯一，新播会 `close` 掉**正在播**的那条 |
| 体积 | ~100KB/条 | ~13KB/条 |

体积代价完全可接受（7 条不到 1MB），换来的是播放稳。
**mp3 那条路的坑是实测踩出来的**：频繁触发时新语音不断掐断正在播的，
听感就是"有的没播出来"；而阻塞调用还卡住了采集循环。

### 但语音本身用的是更年轻的神经语音

本机 SAPI5 **只有 `Microsoft Huihui Desktop` 一个中文语音**，是成年女声、机械，
而且没有更年轻的选项。所以用 **edge-tts 的 `zh-CN-XiaoyiNeural`**
（VoiceTag 场景=Cartoon、性格=Lively）—— 中文语音列表里最年轻自然的一个。

edge-tts 只出 mp3，而本机没有 ffmpeg → 用 **`soundfile`**（自带 libsndfile 1.2+，
支持 mp3 解码）转成 wav。**全程不需要外部可执行文件。**

MCI 通道保留着，只作 mp3 的兜底。

### 语速 vs 时长：这是个取舍，不是两个独立旋钮

**语速调慢会让片段变长**，而报告 §7 要求 1~2 秒（孩子正在思考，长句会打断）。
所以"慢"必须用**压短文案**来换：

| | 旧（Huihui） | 新（Xiaoyi） |
|---|---|---|
| 语速设置 | rate=+2（还加快过） | rate=-10%（放慢） |
| 每秒字数 | 0.30 秒/字 | **0.44 秒/字（慢 47%）** |
| 文案长度 | 7 字 | **压到 4~5 字** |
| 实际时长 | 2.1 秒 | **2.0~2.2 秒** |

结论：**单位语速明显变慢了，但总时长没变长** —— 靠砍字换来的。

重新生成（`tools/make_voice.py`）：

```bash
envs\posture\Scripts\python.exe tools\make_voice.py --all           # 神经语音 -> wav
envs\posture\Scripts\python.exe tools\make_voice.py --rate -15%     # 再慢一点
envs\posture\Scripts\python.exe tools\make_voice.py --engine sapi   # 离线兜底（Huihui）
envs\posture\Scripts\python.exe tools\make_voice.py --list          # 看有哪些语音
```

旧的 Huihui wav 已归档到 `voice\sapi-huihui\`（不删，方便 A/B 对比）。
想切回成年女声：把那里的 wav 拷回 `voice\` 覆盖同名文件即可。

**试听入口**：「家长设置 → 提醒与声音」里每个语音片段都有一个按钮，
试听会忽略静音开关（点了没声音会让人以为功能坏了）。
报告 §7 要求"让孩子听一遍，确认不刺耳、不反感"——就靠这个按钮。

## 必须知道的限制

| 限制 | 说明 |
|---|---|
| **阈值未标定** | `THRESHOLDS` / `SIDE_THRESHOLDS` 是初始值，**必须用真实数据回归**，否则误报率不可控 |
| **摄像头高度** | 放桌面时摄像头约 90~97cm，孩子眼睛 100~115cm，属轻度仰拍（5~10°）。**垫高 10~20cm** 更稳，也让髋部更容易入画（塌腰判定需要） |
| 侧向机位别用 45° | 45° 只能看到前后位移的 71%；纯侧面模式请摆 80~90° |
| 儿童关键点抖动 | 通用模型按成人训练，儿童头身比不同。缓解靠个人基线；根治要靠模型微调 |
| 摄像头后端 | ⚠️ **实测：本机 USB 摄像头（Nebula 02）只有 MSMF / ANY 能打开，DSHOW 按索引 0~3 全部失败**；而笔记本时代恰好相反（DSHOW 可用、MSMF 报错）。**两端结论相反，所以程序只能依次尝试，不能写死**。程序已自动按 DSHOW → MSMF → ANY 试 |
| 摄像头分辨率 | ⚠️ 本机这颗 USB 摄像头**固定 1920×1080 @30fps，不接受降分辨率请求**（实测请求 640×480 / 1280×720 / 1920×1080 读回来都是 1080p）。所以**默认采集值已改为最高档 1080p**，让代码与实际一致。实测代价：1080p 比 720p 每帧只慢 **7.8%（VIDEO 模式 11.4 vs 10.5ms）**，5 FPS 下只占预算 5.7% —— 可以放心用最高档 |
| 只需 5 FPS | 采样率默认 5 FPS 是**刻意的**。坐姿变化是秒级慢过程，调高只会白耗电 |
| 判定靠相对基线 | 阈值随体型/机位/镜头变化，**绝对值不可靠，相对个人基线的偏移才可靠** |
| 暗光敏感 | 光线是影响准确率最大的外部因素，晚上必须开台灯；侧放后注意别变成侧逆光 |
| 髋部常被遮挡 | 侧面下「塌腰」需要髋部可见，写作业时经常拿不到，程序会自动跳过该项（不误报） |

## 代码结构

### 文件分工

| 文件 | 职责 |
|---|---|
| `posture_monitor.py` | **判定逻辑 + CLI**。指标计算、判定、迟滞闸（ReminderGate）、融合、标定自检、bench |
| `posture_engine.py` | **运行时引擎（线程化）**。采集→推理→判定→迟滞→语音，对界面暴露快照与指令 |
| `posture_app.py` | **PySide6 图形界面**。只画界面，不碰摄像头/推理 |
| `tests/test_offline.py` | **103 个离线回归用例**（不需要摄像头和依赖） |
| `config.json` | 家长设置（自动生成） |
| `baseline.json` | 个人基线（自动生成，跟着机位走） |
| `logs/run-YYYYMMDD.log` | 运行日志（自动生成，纯文本，保留最近 7 天；`--no-log` 可关） |
| `review\pending\` `review\done\` | 判定现场图 + 指标 + 家长标注（自动生成，本地，可一键清空） |

### 关键函数

| 函数 / 类 | 职责 |
|---|---|
| `compute_metrics()` | 正面：33 关键点 → 5 个指标（按肩宽归一化）。**含误检帧粗筛** |
| `compute_side_metrics()` | 侧面：颈部前倾角 / 躯干倾角 / 肩耳距离。**像素空间算角度 + 偏航补偿 + 误检筛除** |
| `build_baseline()` | 标定样本 → 基线（取中位数抗抖动，容忍键不一致） |
| `judge()` / `judge_side()` | 当前指标 vs 基线 → 违规问题列表 |
| `fuse()` | 双机位融合判定（纯侧面模式不调用） |
| **`ReminderGate`** | **迟滞 + 两道提醒间隔**。CLI 与 GUI **共用同一份实现**，防止两边规则漂移 |
| `play_reminder()` | 只负责播放（语音 wav/mp3 / 提示音），**不做间隔控制**（间隔归 Gate 管） |
| `sanity_rows()` | 标定结果自检，返回带判定等级的行（CLI 打印 / GUI 上色都用它） |
| **`side_score()`** | 把侧面指标统一成「越大越该报警」（几个指标方向不一致，不统一会扫反） |
| **`suggest_threshold()`** | 用人工审核样本反推建议阈值；**误报权重 1.5×**，同分时优先少误报 |
| **`ReviewStore`** | 判定现场图 + 指标 + 家长标注的本地存储（上限剪枝 / 一键清空 / 隐私） |
| `PostureEngine` | 后台线程引擎；`snapshot()/pause()/resume()/recalibrate()/stop()` |
| `Speaker` | 语音播放。**播放跑在独立线程**，`say()` 只入队（实测 0.18ms 返回）；队列深度 1，新提醒顶掉旧的 |
| **`VideoSource` / `replay()`** | **把录像当摄像头**，离线重跑整条判定链（标定→指标→判定→迟滞→提醒）并输出逐条时间线（`--video`）。只换帧来源，规则仍是同一份实现 |
| `RunLog` | 运行日志落盘：按天一个文件、保留最近 7 天；**写失败静默降级**，绝不影响提醒主功能 |
| `_shrink()` | 缩图（960px 宽），**界面预览与审核缩略图共用**。它**不参与判定**（判定用原始帧）；审核原图另走 `full_frame`。注意 `PREVIEW_MAX_W` 一改，审核缩略图的分辨率也跟着变 |

**迟滞由 `ReminderGate` 统一实现**：单帧越界绝不报警，需连续超标 `SUSTAIN_SEC`(4s) 才提醒；
恢复正常需持续 `CLEAR_SEC`(3s) 才解除。

提醒间隔是**两道闸**，缺一不可：

| 参数 | 默认 | 作用 |
|---|---|---|
| `REMIND_GAP_SEC` | 90s | **同类**问题两次提醒的最小间隔 |
| `REMIND_GAP_ANY_SEC` | **30s** | **任意两次**提醒之间的最小间隔，**跨问题也生效** |

⚠️ 只有前者是不够的 —— 它按问题名分别计时。孩子扭一下、问题在
头前倾／塌腰／低头 之间轮换时，每个问题各自都没到 90 秒却会轮流触发，
**变成每几秒响一次**（实测踩过）。

需求原话：「三十秒之内如果提示过不正确就不提示，**即便不正确的原因也不一样**。」
—— 这正是 `REMIND_GAP_ANY_SEC` 的语义：30 秒内提醒过，就一律不再提醒，
不管这次的原因和上次是否相同。

### 坐正了不发声

**只有"需要纠正"才发声音。** 坐姿正常时程序完全静音：

- 早期在恢复正常时会 `chime("good")` 给个正反馈提示音 —— **已移除**
- 正向激励改用界面表达（绿色大字「坐得真棒！」+ 连续良好计时）
- 唯一保留的提示音是**标定完成**（`chime("done")`）—— 那是系统事件，
  不是坐姿判定，且只响一次，用来告诉家长基线采集好了

这条约束有**源码级回归锁**（测试 H1/H3），防的是以后被无意改回去。

**上面这些是防「抖一下就叫」的关键，不要为了"更灵敏"调小。**

## 已修复的坑（供参考，别再踩）

| 坑 | 症状 | 修法 |
|---|---|---|
| **侧面角度没做宽高比校正** | 16:9 下角度被压扁 44%，12° 阈值实际要求真实 21° → 系统性漏报 | 先 `* w` / `* h` 转像素再 `atan2`。回归锁见测试 B13~B15 |
| **`cap.read()` 会抛异常** | 驱动打个嗝就整个程序崩溃（实测 MSMF 报 `_step >= minstep`） | 包 `read_frame()`，异常一律当"读帧失败" |
| **采集分辨率从不设置** | 一直吃 OpenCV 的 640×480 默认值，关键点明显抖 | 显式设 `CAP_PROP_FRAME_WIDTH/HEIGHT` 到 720p |
| **躯干倾角符号写反** | `sy - hp_y` 恒为负，`trunk_angle` 永远算不出来，「塌腰」永不报警 | 髋在肩下方，取绝对值 |
| **MediaPipe 时间戳倒退** | 重标定时把 `now - t0` 归零 → VIDEO 模式时间戳倒退，推理结果错 | 时间戳基准全生命周期只设一次（`engine._t0`） |
| **迟滞逻辑写两份** | CLI 与 GUI 各写一遍，规则慢慢漂移 | 抽成 `ReminderGate`，两边共用 |
| **便携版 Python 没有 tkinter** | `import tkinter` 直接 ModuleNotFoundError，GUI 一行跑不起来 | 界面改用 PySide6；环境固定用系统 Python 3.12 |
| **pip 装 mediapipe 会撞批量删除护栏** | mediapipe 拉 opencv-contrib-python，替换 cv2 时删几千个文件被拦 | `pip install --no-deps mediapipe` + 手动补齐其余依赖，跳过 contrib |
| **Qt 布局被顶替** | `QFormLayout(page)` 会替掉该页已有布局，报 "already has a layout"，页面排版错乱 | 无父构造 `QFormLayout()`，再 `page.layout().addLayout(...)` |
| **离屏平台的字体数是 0** | `--selftest` 恒显示"系统默认"，看着像字体没选中 | 离屏模式 Qt 找不到自己的字体目录，属正常；真实运行用系统字体 |
| **提醒间隔按问题分别计时** | 头前倾／塌腰／低头 各自计时，轮流触发 → **每 4~8 秒响一次** | 增加「任意两次提醒」的全局下限 `REMIND_GAP_ANY_SEC`（**默认 30s，跨问题也生效**） |
| **坐正了会响一声正反馈提示音** | 坐姿没问题也被声音打扰（需求明确不要） | 移除该调用；正向激励改用界面表达。加了源码级回归锁（测试 H1/H3） |
| **语音播放阻塞推理线程** | MCI 的 open/close 是阻塞调用，一播语音就卡住采集循环 | 播放移入独立线程，队列深度 1（实测 say() 从上百 ms 降到 0.18ms） |
| **新语音掐断正在播的那条** | `_say_mci` 开头就 `close` 别名，频繁触发时上一条被截断（听感就是"有的没播出来"） | 单线程串行播放，同一时刻只有一条在播；入队时顶掉的是**还没开始播**的 |
| **播放失败没有任何线索** | 只报"已播放/退回提示音"，说不出为什么 | 工作线程通过 on_log 汇报失败原因（含 MCI 错误串） |
| 写死 DSHOW 后端 | 报"打不开任何摄像头"，其实设备在 | 按 DSHOW→MSMF→ANY 依次尝试 |
| 误检帧污染基线 | **画面里没人也能"标定成功"**，基线是垃圾（span=0.037） | 加合理性粗筛，拒绝不可信帧 |
| 无人的帧拉低基准 | 测出 13.2ms，实际含人要 19.2ms（乐观 40%） | 基准分开统计含人/无人帧，检出率 <50% 时主动报警 |
| 缩输入分辨率想省时间 | 实测 640px vs 1280px 只差 2.6%，白折腾 | 该降级手段已从方案中移除 |
| 手部模型降分辨率也不省时间 | 实测 1280x720 与 640x360 都是 ~18ms（内部裁 ROI） | 同上；别在这上面花心思 |
