## 0. 总览：要做什么

| 阶段 | 做什么 | 预计耗时 | 通过标准 |
|---|---|---|---|
| P-1 | 环境准备（venv + 模型） | 5 分钟 | `--list-cameras` 能看到 2 路 |
| P-0 | **性能自测**（最关键） | 3 分钟 | 余量 > 3x |
| P-1 | 单机位试跑（正面） | 15 分钟 | 标定成功、能正确判定低头/歪头 |
| P-2 | 双机位布置与试跑 | 30 分钟 | 两路都标定成功、融合判定生效 |
| P-3 | 阈值标定 | 需要录制数据 | 误报率 < 10% |

**关键认知（决定了整个方案的可行性）**：坐姿变化是**秒级慢过程**，配合 3~5 秒持续时间过滤，
所以推理**只需 2~5 FPS**，不是 30 FPS。5800U 的余量有 7~8 倍。
**如果哪天觉得卡，先看是不是采样率设高了，别急着怪算力。**

## 1. 硬件布置（先摆好再动代码）

### 1.1 摄像头分工——没有选择余地

| 摄像头 | 位置 | 只能承担 |
|---|---|---|
| 笔记本内置 | 屏幕上边框，**焊死不能挪** | **正面**（孩子坐在屏幕前时） |
| USB 摄像头 | 可自由摆放 | **侧面 45°** |

⚠️ **别指望内置摄像头拍侧面**——要把笔记本转过去，孩子就看不了屏幕了。

### 1.2 摆位参数

| 机位 | 位置 | 高度 | 距离 | 画面要求 |
|---|---|---|---|---|
| **正面**（内置） | 屏幕上方，正对孩子 | 与坐姿头部齐平或略高 | 60~80 cm | 上半身完整入画（肩、头必须可见） |
| **侧面**（USB） | 孩子**侧方 45°** | 与头部齐平或略高 | 100~150 cm | 头 + 肩 + 尽量带到髋 |

**三不要**：
- **不要仰拍**（摄像头低于桌面）——关键点置信度会明显下降
- **不要逆光**——背景别对着窗户
- **不要放太远**——肩宽至少要占画面 6%（程序会自动拒绝不达标的帧）

### 1.3 USB 线长

摄像头要放到侧边 1~1.5m，线得能连回笔记本。一般 USB 摄像头线 1.5~2m，
不够就加**带供电的 USB 延长线**（5m 以内可靠，再长要用主动式延长线）。

### 1.4 光照

**光线是影响准确率最大的外部因素。** 暗光下关键点抖动明显加剧。
→ **晚上务必开台灯**，并让光源在孩子正前方偏上，避免阴影投在脸上。

## 3. P-0 性能自测（**最该先做的一件事**）

```bash
envs\posture\Scripts\python.exe posture_monitor.py --bench --bench-frames 100
```

### ⚠️ 跑之前：**必须让一个人真的坐在摄像头前**

这是本次调研踩到的最重要的坑：**MediaPipe 是两段流水线——先跑人体检测器找人框，找到才跑关键点模型。**
画面里没人时关键点模型整段被跳过，测出来的数字会**乐观 40%**。

**正确做法**：人坐好、光线正常，再跑。看输出里的「检出成功率」：

| 检出率 | 意味着 |
|---|---|
| > 70% | ✅ 数字可信 |
| 30~70% | ⚠️ 参考「含人帧」那一行，别用总均值 |
| < 30% | ❌ 结果作废，重跑 |

### 期望输出

```
===== 基准结果（pose_landmarker_lite.task）=====
  采样帧数     : 100
  检出成功率   : 95/100  (95%)

  【含人帧】   n= 95  mean=  26.3ms  p95=  30.1ms   <- 这才是真实成本
  【无人的帧】 n=  5  mean=  18.0ms  p95=  22.0ms

  [成本拆解] 检测器 ≈ 18.0ms（68%），关键点模型 ≈ 8.3ms（32%）
             -> ROI 跟踪跳过全图检测器可省掉其中约 68%

  ---- 结论（按 26.3ms / 帧）----
  等效帧率   : 38.0 FPS
  判定需要的帧率仅 5 FPS
  余量       : 7.6x  ->  ✅ 完全胜任
```

**判读最后一行的余量**：

| 余量 | 结论 | 动作 |
|---|---|---|
| > 3x | ✅ 完全胜任 | 按默认 5 FPS 跑，**不需要**用 faex1 |
| 1.5~3x | ⚠️ 够用 | 把 `FPS_SAMPLE` 从 5 降到 3 |
| < 1.5x | ❌ 不足 | 才需要考虑降级（见调研报告 §11） |

- [ ] 基准跑完，余量 = ______x
- [ ] 真实含人帧耗时 = ______ ms
- [ ] 结论：□ 完全胜任  □ 需要降采样率

> 本机 7940H 实测参考：含人帧 **19.2ms / 52 FPS**。5800U 预计 26~27ms / 37 FPS。

## 4. P-1 单机位试跑（先只上正面）

**别一上来就双机位。** 先确认单路跑通，出问题好定位。

```bash
envs\posture\Scripts\python.exe posture_monitor.py --camera 0 --calib 10
```

流程：

| 步骤 | 屏幕提示 | 你要做的 |
|---|---|---|
| 1 | `CALIB 正面 0` → 递增到 15 | **让孩子端坐**，别低头别说话，保持 10 秒 |
| 2 | `[标定完成] 正面 基线 = ...` | 确认打印出了 5 个指标 |
| 3 | 进入监测，窗口实时显示状态 | 让孩子故意低头，看是否 4 秒后报警 |

### 标定阶段的期望输出

```
[标定完成] 正面 基线 = head_tilt=0.021, span=0.312, shoulder=0.014, head_off=0.081, head_drop=1.213
```

**合理性自检**（这一步很重要，别跳）：

| 指标 | 合理范围 | 不合理说明 |
|---|---|---|
| `span`（肩宽） | **0.15 ~ 0.60** | 太小/太大 → 机位距离不对，或帧被误检 |
| `head_drop` | **0.8 ~ 2.0** | 超出 → 关键点错乱 |
| `head_tilt` / `shoulder` | 接近 0 | 明显偏大 → 孩子标定时就没坐正，重新标 |

> **已修的 bug**：程序现在会自动拒绝"检测器误检"的垃圾帧
> （曾出现肩宽仅占画面 3.7% 却被当成有效样本的情况）。
> 所以**画面里没人时会正确地标定失败**，这是预期行为，不是程序坏了。

- [ ] 标定成功，基线 5 个指标都在合理范围
- [ ] 故意低头 → 4 秒后报警
- [ ] 恢复正常坐姿 → 3 秒后解除
- [ ] 连续跑 10 分钟不崩、不卡

## 5. P-2 双机位（正面 + 侧面 45°）

确认单路没问题后，加侧面：

```bash
envs\posture\Scripts\python.exe posture_monitor.py --camera 0 --camera2 1 --calib 10
```

会出现**两个预览窗口**：`Posture-正面` 和 `Posture-侧面`。

### 为什么值得上双机位

| 能力 | 单正面 | 单侧面 | **双机位** |
|---|---|---|---|
| 低头 / 塌腰 | ✅ | ✅ | ✅ |
| 歪头 / 歪肩 | ✅ | ❌ | ✅ |
| 距离过近 | ✅ | ❌ | ✅ |
| **头前倾（CVA）** | ❌ 正面测不出 | ✅ | ✅ |
| **判定「含胸驼背」** | ❌ | ❌ | ✅ **两路互证** |

**融合规则**：正面看到「低头」**且** 侧面看到「头前倾」→ 升级判定为「**含胸驼背**」。
这是单路做不到的——正面看不到前后关系，侧面看不出左右对称性。

### 侧面机位的特殊性

- 侧面下左右肩在画面里几乎重合，**不能用肩宽归一化**，
  所以侧面指标一律用**角度（度）**——角度天然与距离、体型、分辨率无关，无需归一化。
- **躯干倾角需要髋部可见**，但孩子写作业时髋部常被桌面遮挡。
  拿不到时程序会自动跳过这项（不误报），只做颈部前倾判定。这是设计如此，正常。

### 标定时的注意

**两个机位要同时标定**，所以孩子要保持坐姿直到两个窗口都采集够样本。
若某一路始终看不到人，60 秒后会自动失败并告诉你哪一路样本不足。

- [ ] 两个窗口都有画面，且都拍到了孩子
- [ ] 两路基线都打印出来且数值合理
- [ ] 低头 + 头前倾同时出现时，显示「含胸驼背」
- [ ] 遮挡侧面摄像头 → 正面仍能独立工作（不崩）

## 6. P-3 阈值标定（这一步必须有真实数据，别跳）

**原型里的阈值是未标定的初始值，不能长期直接用。**

| 参数 | 当前值 | 含义 |
|---|---|---|
| `THRESHOLDS["head_drop"]` | 0.10 | 头部下沉 10% 算低头（≈下移 3~4cm） |
| `THRESHOLDS["head_tilt"]` | 0.06 | 双耳高度差 |
| `THRESHOLDS["shoulder"]` | 0.05 | 双肩高度差 |
| `THRESHOLDS["too_close"]` | 0.15 | 头肩尺度膨胀 15% |
| `SIDE_THRESHOLDS["neck_angle"]` | 12.0° | 侧面颈部前倾角增量 |
| `SUSTAIN_SEC` | 4.0 s | 连续超标多久才提醒 |
| `CLEAR_SEC` | 3.0 s | 恢复正常多久解除 |
| `REMIND_GAP_SEC` | 90 s | 同类问题最小提醒间隔 |

### 标定方法

> ⚠️ **已改为「使用中顺手标注」**（2026-09-22）：原来的「录 15~20 分钟视频 → 逐帧人工标注」
> 走不通 —— 家长不会做，数据收不上来，而误报率这个验收指标就永远算不出来。
> 现在是：提醒响了自动存现场图 → 家长在「家长设置 → 审核判定」逐条点「对／不对」
> → 该页直接反推建议阈值。详见 [`03-side-only-plan.md`](03-side-only-plan.md) §8.7。

1. 正常使用程序几天（数据自动积累，不用专门录视频）
2. 在「家长设置 → 审核判定」逐条审核，标出哪些是误报、哪些是漏报
3. 看该页底部的**建议阈值**，以及"改后误报/漏报"的对比
4. 决定是否采纳，采纳后到「判定阈值」页改

**验收标准**：误报率 < 10%。**误报比漏报更致命**——叫得太勤，孩子三天就把程序关了。

### ⚠️ 这三个参数不要为了"更灵敏"调小

`SUSTAIN_SEC` / `CLEAR_SEC` / `REMIND_GAP_SEC` 是防「抖一下就叫」的关键。
调小会让提醒变成噪音，直接毁掉产品。

## 7. 语音提醒配置

原型默认用系统提示音。要换成语音：

```
repos\p0-prototype\voice\
    低头.wav
    歪头.wav
    歪肩.wav
    太近.wav
    头前倾.wav
    塌腰.wav
    含胸驼背.wav
```

**做法**：用 TTS **离线预生成**短句，**不要运行时调在线 TTS**。

| 要求 | 说明 |
|---|---|
| 零延迟 | 本地文件播放，不走网络 |
| 语气 | **鼓励性**，不是命令式。「抬头挺胸收下巴，这样真棒」>「坐直了！」 |
| 时长 | 短，1~2 秒。孩子正在思考，长句会打断 |
| 音量 | 温和，别吓人。笔记本自带 B&O 双扬声器够用 |

- [ ] 生成 7 个语音文件
- [ ] 实测播放延迟 < 100ms
- [ ] 让孩子听一遍，确认不刺耳、不反感

## 8. 故障排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| 打不开任何摄像头 | **后端不对**（DSHOW 在这台机器上枚举不到设备） | 加 `--backend MSMF`；或先跑 `--list-cameras` |
| 打开了但读不到帧 | 被其他程序占用 | 关掉相机 App / 会议软件 / 用到摄像头的浏览器标签页 |
| `--list-cameras` 看不到 USB 那颗 | 线材/供电 | 换 USB 口（优先主板直连口，别用扩展坞的） |
| 标定一直不成功 | 画面里没拍到完整上半身 | 调整机位与距离；确认光线充足 |
| 基线数值离谱（如 `span=0.03`） | 检测器误检 | 已由程序自动拒绝；若仍出现，说明画面质量太差，改善光照 |
| 频繁误报 | `SUSTAIN_SEC` 太小 / 阈值未标定 | 先做 P-3 标定 |
| 完全没反应 | 孩子不在画面里 | 检查是否被遮挡、是否出画 |
| 侧面总拿不到躯干倾角 | 髋部被桌面遮挡 | **正常**，属设计如此。可把摄像头垫高一点、往后拉一点试试 |

## 10. 运行参数速查

| 参数 | 用途 |
|---|---|
| `--list-cameras` | 列出可用摄像头（**排查第一步**） |

## 11. 已知限制（别对它们抱期望）

| 限制 | 说明 |
|---|---|
| **阈值未标定** | 必须做 P-3，否则误报率不可控 |
| **儿童关键点抖动** | 通用模型按成人训练，儿童头身比不同。缓解靠个性化基线；根治要靠 faex1 微调模型 |
| **握笔姿势测不了** | 需要含手部关键点的模型（如 DWPose，133 点），当前是 33 点 |
| **髋部常被遮挡** | 躯干倾角在写作业场景下经常拿不到，属正常 |
| **光线敏感** | 暗光下识别率骤降，晚上必须开台灯 |
