# 握笔姿势检测 · 可行性评估

日期：2026-09-26　｜　结论：**可行，但必须做成独立软件 + 独立摄像头，不能并入现有坐姿程序**

---

## 0. 一句话结论

| 判断 | 内容 |
|---|---|
| ❌ **不能复用现有侧视摄像头** | 两者几何上**互斥**，不是调参能解决的 |
| ✅ **独立软件可行** | 所有商用方案都是这个形态（桌面俯视摄像头） |
| ⚠️ **只能做粗判** | 文献实测手部关节角误差 22.5°，与我们要分辨的差异同量级 |
| 🔴 **最优先的一步是「验证看得见」** | 这一关不过，算法再好也没用 —— 所以给了个工具，0 成本可测 |

---

## 1. 先拆检测目标：每类错误需要什么才能测

不先拆清楚，讨论"能不能做"就是空的。

| 要判的错误 | 需要测的量 | 21 个手部点够吗 | 难度 |
|---|---|---|---|
| **拳握 / 全掌握笔** | 手指是否收拢包住笔杆 | ✅ 够（形态差异 >60°，远超误差） | 低 |
| 四指握笔 | 中指/无名指/小指是否都搭在笔上 | ⚠️ 部分够，遮挡多 | 中 |
| **拇指包住食指** | 拇指尖与食指各关节的相对位置 | ⚠️ 勉强（差异约 10~30°，与 22.5° 误差同量级） | 高 |
| **拇指食指相碰** | 拇指尖↔食指尖距离 | ✅ 够（这是**距离**量不是角度量，容忍度高） | 低-中 |
| **握得太低（挡视线）** | 手指 ↔ **笔尖** 的距离 | ❌ **不够，必须定位笔** | 高 |
| 笔杆角度 | 笔杆两端连线与纸面夹角 | ❌ **不够，必须定位笔** | 高 |
| 勾腕 | 手腕与**前臂**的夹角 | ❌ **不够 —— 手部模型只有手腕点，没有前臂** | 中 |

**结论**：纯手部关键点能覆盖 **2~3 项**，而且都是粗判。
要覆盖「握得太低」「笔杆太直」这两项——**恰恰是最影响视力和书写质量的两项**——
必须**检测笔本身**，那就需要自定义训练数据。

> 参考：专利 CN114399786A（学习桌视觉纠正握笔系统）用的就是**笔尖投影点 + 笔杆顶点**算
> `tan(夹角)`，即必须先把笔定位出来。CN118196829A 走的是手部关键点 → 评分。
> 两条路都有人走，但"要测笔角度就得先找到笔"这件事绕不过去。

## 2. 三个硬约束

### 2.1 相机几何：和现有坐姿检测互斥（最关键）

| | 现有坐姿（侧面） | 握笔所需 |
|---|---|---|
| 取景 | 上半身（含头颈躯干） | 手 + 笔，约 15×15cm |
| 距离 | 1~1.5m | 30~60cm |
| 角度 | 侧方 80~90° | 俯视 / 大角度斜俯 |
| **手在画面里** | **约 60~100px** | **需要 ≥200px** |

一个摄像头无法同时满足这两行：**要拍到躯干，手就只有几十像素；要把手拍大，身体就出画。**

而且侧视角下**笔杆几乎与视线平行、被手指完全遮住**——连"看得见笔"都做不到。

→ 必须**加第二个摄像头**，或把现有程序迁到桌面俯视视角（那就放弃了躯干/颈部的侧面几何，
而现有全部阈值都建立在那个几何上）。

### 2.2 精度余量：误差和信号是同一个量级

| 证据 | 数值 | 含义 |
|---|---|---|
| MediaPipe 手部关节角 vs Vicon 真值 RMSE | **22.5°** | 我们要分辨的差异只有 10~30° |
| （对比：Leap Motion Controller 2） | 14.8° | 专用红外手部设备明显更好，且**不随运动速度退化** |
| 误差最大的关节 | **PIP（近端指间关节）** | 恰恰是判握笔最需要的那个关节 |
| 静态握物体时的手部检出率 | 93.2%~99.2% | |
| **运动中**的检出率 | **83.2%~84.8%** | 写字一直在动 |
| 曾观测到的连续丢失 | **约 4 秒**完全取不到有效坐标 | 遮挡+运动场景 |

→ **细分类不成立**。只能做"拳握 vs 三指"这种大形态差异的粗判。
→ 4 秒丢失意味着判定必须**做在检出率门控之上**：跟不住的时候不下结论，否则会疯狂误报。

### 2.3 "正确握笔"本身没有唯一标准

- 国内学校标准是**三指执笔法**（拇指食指捏、中指抵、笔杆靠食指根部、离笔尖约 2.5~3cm）
- 但职业治疗领域接受**多种功能性握法**，四指握法对某些手型更省力
- 孩子的手在发育中，握法会自然变化

→ 阈值必须**家长可配置**，且要容忍个体差异。否则误报会多到孩子两天就不用了。

## 3. 本次实测（本机）

| 项目 | 结果 |
|---|---|
| 手部模型 | `hand_landmarker.task`，**7.5MB**，已下载到 `bench/models/` |
| 推理耗时 | 1280x720 **17.7~18.7ms**；640x360 **一样**（内部裁 ROI，降分辨率省不了时间） |
| 与现有 Pose 的关系 | 同一套 Tasks API，接起来很顺；但 **Pose 的 33 个点不含手部指节**，是两个模型 |
| 摄像头数量 | **只有 1 个**（DSHOW 索引 0 @1280x720）→ 做握笔**必须新增硬件** |
| 算力预算 | 现有采样 5 FPS = 每帧 200ms 预算；手部模型 +18ms，**算力完全够** |

**附带确认的一件事**：本项目里反复踩的「MediaPipe 时间戳必须单调递增」这个坑，
在手部模型上同样成立（`detect_for_video` 全生命周期不能倒退）。
在握笔程序里要一次性设计好，别再返工第三次。

## 4. 方案对比

| 方案 | 硬件成本 | 可行性 | 说明 |
|---|---|---|---|
| **A 复用现有侧视相机** | 0 | ❌ **不可行** | 手只有几十像素；侧视下笔被手指完全遮住 |
| **B 独立软件 + 第二摄像头（桌面俯视）** | USB 摄像头+支架，约 **50~150 元** | ✅ **推荐** | 与坐姿程序并存互不干扰；所有商用方案都是这个形态 |
| **C 手机当摄像头**（旧手机 + DroidCam/IRIUN） | 0（有旧手机即可） | ✅ **先验证用** | 适合**先回答"看得清不清"**，不用先买设备 |
| D 专用硬件（Leap Motion 2 / 压感数位板） | 数百~上千元 | ✅ 精度最好 | 14.8° 误差且不随速度退化；但贵，且只覆盖手部区域 |
| **E 不做视觉：握笔器 + 家长抽查** | **5~20 元** | ✅ 最省 | 物理约束，成熟几十年，**当天见效** |

## 5. 建议路线：分四关，每关都可能叫停

### 第 0 关：验证「看得见」（0 成本，今天就能做）🔴 最重要

拿手机从桌面斜上方拍 2~3 段孩子写字的短视频；或用旧手机装 DroidCam 当摄像头，
然后跑：

```bash
envs\posture\Scripts\python.exe tools\check_hand_view.py --image D:\握笔照片.jpg
envs\posture\Scripts\python.exe tools\check_hand_view.py --camera 0 --with-pose
```

只看两个数：

| 指标 | 门槛 | 不达标说明什么 |
|---|---|---|
| 手部宽度 | **≥ 200px** | 太小 → 什么算法都白搭，先改机位/换更近的相机 |
| 检出率（写字过程中） | **≥ 90%** | 掉得厉害 → 遮挡或光照问题，先解决再加上判定 |

**这一关不过，后面全是空谈。** 而且用 `--with-pose` 能**直接看到**：
身体取景合适的时候手只有几十像素 —— 这就是 §2.1 那个几何冲突的现场证据。

### 第 1 关：只做粗判 3 项

拳握 / 拇指食指相碰 / 握得过低（后者需要笔定位，见第 2 关）。
**刻意不做细分类**，因为精度不支持。延误阈值直接用现有的 `suggest_threshold`。

### 第 2 关：加笔检测

自定义训练一个小目标检测/分割模型，需要标注数据 —— 可以**直接复用现有的
「审核存图」机制**收集，不用重新造轮子。

### 第 3 关：独立 GUI + 语音

可复用现有 ~60% 代码（见下）。

## 7. 风险排序

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | **"看不清"** | 🔴 最高 | 第 0 关先回答，不达标就停 |
| 2 | **误报** | 🟠 很高 | 写字过程中手形态频繁变化 + 正确标准有争议。**误报比漏报致命**（沿用坐姿项目结论）。检出率门控 + 迟滞 + 家长可配阈值 |
| 3 | 笔定位 | 🟠 高 | 笔细、反光、与手指互相遮挡，需要自定义数据 |
| 4 | 长时间丢失 | 🟡 中 | 用检出率门控，跟不住时不下结论 |

---

## 8. 建议的验收标准

- 手部检出率 **≥ 90%**（写字过程中，不是静止摆拍）
- **误报率 < 10%**（沿用坐姿项目的标准，靠家长审核统计）
- **只对"粗形态"下结论**，不对细分姿态给判断
- 三条有一条不达标 → **退回方案 E（握笔器）**，不要硬做

## 9. 需要你决策的两件事

1. **先做第 0 关验证，还是直接买摄像头？**
   建议**先验证** —— 手机就有，0 成本，而且万一不达标能省下买设备+几周开发。

2. **若要做：独立程序，还是把坐姿程序也迁到桌面俯视视角？**
   建议**独立程序**（你说的"单独写一个软件"是对的）：存活率高、互不干扰，
   而且现有坐姿程序的东西不用推倒重来。
