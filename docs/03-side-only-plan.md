# 方案变更 · 纯侧面单路（side-only）

| 项目 | 内容 |
|---|---|
| 变更日期 | 2026-09-22 |
| 变更前 | 单机双摄：内置头拍正面 + 外接 USB 头拍侧面 45°（见 01 报告 §11） |
| **变更后** | **纯侧面单路**：笔记本侧放到孩子侧方 80~90°，只用内置摄像头 |
| 变更原因 | ① 孩子的核心问题是驼背 / 头前倾，正面在几何上测不出；② 纸笔作业，笔记本不必给孩子看屏幕；③ 不再折腾第二颗摄像头与支架 |
| 影响面 | 判定指标、阈值单位、机位摆位、语音清单、降级阶梯 |

---

## 1. 为什么这个变更是合理的

正面视角测不出驼背**不是模型能力问题，是几何决定的**——正面看，「前后方向」被压扁成几乎没有信息。
所以正面那一路对用户真正关心的问题本来就没有贡献。砍掉它不是降级，是**把资源集中到唯一有效的那一路上**。

而且背靠一个连带收益：**45° 那个斜角本来就是为了兼顾左右对称性才做的折中，现在不需要了。**

| 机位偏航角 | 前后位移可见比例 sin(yaw) | 后果 |
|---|---|---|
| 0°（正面） | 0% | 完全测不出前后关系 |
| 45°（原方案） | 71% | 前后位移被压缩 29%，偏保守 |
| **80°** | **98%** | 接近无损 |
| **90°（正侧，推荐）** | **100%** | 前后关系测得最真 |

> **结论：纯侧面模式应当把机位摆到 80~90°，不要沿用原来的 45°。**
> 程序已内置 `--side-yaw`，按 1/sin(yaw) 把被压缩的量还原回矢状面，使阈值始终是真实度数。

## 2. 能力取舍（认账清单）

| 坐姿问题 | 变更前（双机位） | 变更后（纯侧面） | 说明 |
|---|---|---|---|
| **头前倾（CVA）** | ✅ | ✅ **保留** | 核心问题，侧面专治 |
| **驼背 / 含胸** | ✅（两路互证） | ➖ **退化为「头前倾」** | 融合升级项做不出来，但结论方向一致 |
| **塌腰** | ✅ | ✅ **保留** | 需髋部可见，常被桌面遮挡（拿不到就跳过） |
| 低头（头下探） | ✅ | ✅ **保留** | 用肩-耳距离收缩判定（新增） |
| 歪头 | ✅ | ❌ 放弃 | 冠状面（左右），侧面原理上测不到 |
| 歪肩 | ✅ | ❌ 放弃 | 同上 |
| 距离过近 / 趴桌 | ✅ | ➖ **部分保留** | 「趴桌」由 `sh_ear_len` 收缩覆盖；「离屏幕太近」在纸笔场景本就不适用 |
| 握笔姿势 | ❌ | ❌ | 需 DWPose 类含手部关键点的模型，未变 |

**一句话**：丢掉的两项（歪头、歪肩）是冠状面的，对"驼背含胸"这个主诉没有信息量。

## 3. 机位摆位：这一步最容易做错

### 3.1 摄像头高度：放桌面会略偏仰拍（可接受，但垫一点更好）

笔记本侧放、直接放在桌面上时的高度关系：

| 项 | 高度 | 说明 |
|---|---|---|
| 桌面 | 70~75cm | 标准学习桌 |
| 屏幕上边框摄像头 | **90~97cm** | 屏高约 18cm（13.3" 16:10）+ 转轴 1~2cm |
| 小学生坐姿眼睛 | **100~115cm** | 椅面 38~43cm + 坐姿眼高 62~72cm |

**摄像头比眼睛低约 3~25cm，即轻度仰拍（约 5~10°）。**

这个量级**不致命**（正面机位同样是这个几何关系，原方案也已接受），
但原任务书把「不要仰拍」列为硬约束，且对**侧面**还有第二个代价：

> 摄像头太低 → 视线几乎贴着桌面 → **髋部更容易被桌子挡住** → 「塌腰」判定拿不到数据。

而髋部可见性正是纯侧面模式最缺的东西（指标本就不多，见 §9 风险 1）。

> **结论：建议把笔记本垫高 10~20cm，让摄像头接近孩子眼睛高度，并适当往后拉。**
> 一摞书 / 纸箱 / 矮凳即可，**不需要买支架**。

### 3.1.1 ⚠️ 机位摆错的失败方式是「静默失效」，必须验证

如果把笔记本正常摆在孩子**正前方**就跑（也就是按老方案的正面机位），
程序**不会报错、不会崩溃，而是永远不提醒**：

正面视角下，**同一侧的耳和肩几乎落在一条竖直线上**，`dx ≈ 0`，
于是 `neck_angle` 恒接近 0°，`trunk_angle` 同理 —— 指标算得出来，但全是噪声，
`judge_side` 永远判"坐姿良好"。

这种"看起来在跑、日志也正常、就是不提醒"的失败最难发现。
所以摆完机位**必须验证**，不能靠"看着像在跑"：

**做法**：打开「家长设置 → 机位检查」页，点「开始观察」，
**让孩子往前伸一下头再坐回去**，看「颈部前倾角摆幅」涨到多少：

| 摆幅 | 判定 | 动作 |
|---|---|---|
| ≥ 10° | ✅ 机位没问题 | 可以开始用 |
| 5~10° | ⚠️ 勉强可用 | 再往侧面转一点，灵敏度会明显更好 |
| < 5° | ❌ 太正对孩子了 | 转到 80~90° 正侧 |

> 判据用**摆幅（观察窗口内 max − min）**，有两个好处：
> ① 不能看当前值 —— 家长多半在孩子正常坐着时打开这一页，当前值天然正常，会误报"机位不对"；
> ② 摆幅**不需要基线**，所以**不用等标定跑完就能验机位**。标定要 10 秒且需孩子坐正，
> 而"先验机位、再标定"的顺序更顺 —— 机位不对时标出来的基线本身也没意义。

### 3.2 摆位参数

| 项 | 要求 |
|---|---|
| 位置 | 孩子**侧方 80~90°**（不是 45°），笔记本机身转向孩子侧面 |
| 高度 | 接近孩子眼睛高度（100~115cm）；放桌面约 90~97cm 可接受，**垫高 10~20cm 更稳** |
| 距离 | 100~150 cm（太远会让头肩过小、关键点抖动；太近容易丢关键点） |
| 画面 | 头 + 肩**必须**入画；尽量带到髋（带不到只影响「塌腰」判定） |
| 朝向 | 屏幕转到孩子看不见也没关系（纸笔作业不需要看屏幕） |
| 光线 | 光源在孩子前上方**且照到侧面**。⚠️ 侧放后原来正面的台灯可能变成侧逆光，需实测 |
| 供电 | 长期挂机，**插电**并关闭睡眠/关屏 |

### 3.3 三不要

- 不要仰拍（见 3.1，用垫高解决）
- 不要侧逆光（把孩子拍成剪影，关键点直接失效）
- 不要贴太近（头肩撑满画面反而容易丢关键点）

## 4. 指标与阈值（侧面单路）

| 指标 | 算法 | 单位 | 初值阈值 | 检出问题 |
|---|---|---|---|---|
| `neck_angle` | 肩→耳 连线与竖直方向夹角（像素空间，偏航补偿后） | 度 | 相对基线 **+12°** | 头前倾（含低头，两者在矢状面内不可分） |
| `trunk_angle` | 髋→肩 连线与竖直方向夹角（髋可见时） | 度 | 相对基线 **+8°** | 塌腰 |
| `sh_ear_len` | 肩→耳 直线距离 | px | 相对基线**收缩 12%** | 低头 / 趴桌 / 头下探 |

**三条不变的原则：**
1. 一律用「相对个人基线的偏移」，不用绝对阈值（阈值随体型、机位、镜头变化）
2. 迟滞：连续超标 `SUSTAIN_SEC`=4s 才提醒，恢复 `CLEAR_SEC`=3s 才解除
3. 同类问题最小间隔 `REMIND_GAP_SEC`=90s（防高频打断）

⚠️ **阈值仍是未标定的初始值**，必须做 P-3 用真实数据回归。

## 5. 本次连带修复的两个几何错误

### 5.1 宽高比没校正（严重）

MediaPipe 输出归一化坐标：x 除以画面宽、y 除以画面高，**两者尺度不同**。
旧实现直接 `atan2(dx_norm, dy_norm)`，得到的不是真实角度。

16:9 画面下角度被压扁约 **44%**：

| 真实前倾角 | 旧实现测出 | 偏差 |
|---|---|---|
| 12.0° | 6.8° | 少 44% |
| 16.5° | 9.5° | 少 43% |

**后果**：侧面阈值（12°）实际相当于要求真实 21° 才报警 → **系统性漏报**。
已修复为「先乘回像素宽高、再算角度」。回归锁见 `tests/test_offline.py` 的 B13~B15。

### 5.2 躯干倾角符号错误（新引入后当即修掉）

髋部在肩**下方**（画面 y 更大），写成 `sy - hp_y` 会恒为负，
导致 `trunk_angle` 永远算不出来、「塌腰」永远不报警。已改为取绝对值。

## 8. 软件形态：图形界面（2026-09-22 追加要求）

需求原文：「软件要求图形界面，方便孩子操作」。

### 8.1 分层（关键：判定逻辑只有一份）

```
posture_monitor.py   判定逻辑 + CLI    ← 纯数学，60 个离线用例锁着
      ↑  共用（ReminderGate / judge_side / sanity_rows）
posture_engine.py    后台线程引擎      ← 采集+推理+判定+迟滞+语音
      ↑  快照 / 指令
posture_app.py       PySide6 图形界面  ← 只画界面
```

**为什么必须分层**：迟滞逻辑（连续 4 秒才提醒）如果 CLI 写一遍、GUI 再写一遍，
两条路径迟早漂移——而这恰好是最容易毁掉产品的参数。所以抽成 `ReminderGate` 共用。
同理，`sanity_rows()` 也做成返回结构化结果，CLI 打印、GUI 上色都用它。

**为什么引擎必须独立线程**：单帧推理约 20ms、采样 5 FPS 看着不重，
但 `cap.read()` 会阻塞，标定阶段还要连跑 10 秒——放 UI 线程里界面会在最关键时刻卡死。

### 8.2 界面设计（依据报告 §8）

| 原则 | 做法 |
|---|---|
| 零操作启动 | 双击即开始监测，孩子不需要按任何按钮 |
| 先看脸色再看字 | 大色块 + **手绘表情**（QPainter 画，不用 emoji，避免字体差异变方块） |
| **不用红色** | 警示用暖橙（#E8A33D）。红 = 惩罚感，会让孩子想关掉程序 |
| 正向激励 | 坐得好时绿色大字「坐得真棒！」，正向指标放最显眼处 |
| 设置隔离 | 阈值/标定/提醒节奏全在「家长设置」，孩子界面看不到 |
| 一键重标定 | 机位动了之后，家长点一下即可，不需要命令行 |
| **机位检查页** | 量化确认侧面机位摆对没（见 §3.1.1）—— 这个错误是静默失效，必须验证 |

三个入口：`启动坐姿小卫士.bat`（无黑框）、`调试模式.bat`（保留控制台）、`演示模式.bat`（不接摄像头看界面）。

### 8.3 工具包选型：为什么是 PySide6

**tkinter 在本机不可用**——实测 WorkBuddy 自带的便携版 Python 3.13 **不含 tkinter**，
`import tkinter` 直接 `ModuleNotFoundError`。tkinter 依赖 Python 发行版自带的 tcl/tk，
换个 Python 就没了；而 Qt 是自带二进制的 pip 包，不受发行版影响。

| 候选 | 结论 |
|---|---|
| **PySide6（Qt）** | ✅ 采用。pip 直装、自带二进制、QSS 能做圆角大按钮和平滑中文。LGPL 个人用无约束 |
| wxPython | ❌ 未采用。Windows 轮子对较新 Python 版本常滞后，pip 可能转本地编译并失败 |
| LVGL | ❌ 不对口。嵌入式/单片机 GUI 库，桌面要自己接显示驱动 |
| tkinter | ❌ 本机不可用（见上）；且控件陈旧，做儿童界面吃力 |

### 8.4 环境约束（照抄 requirements.txt 的安装步骤可全部避开）

1. **必须用系统 Python**：`C:\Users\tmpee\AppData\Local\Programs\Python\Python312\python.exe`（3.12.10）
2. **mediapipe 必须 `--no-deps` 安装并跳过 opencv-contrib-python**：
   它与 opencv-python 同时提供 cv2，pip 替换时会删除几千个文件，
   在受限环境下会撞上批量删除护栏而中断。
   **已实测**：不装 contrib 也能跑通原生推理（首次 17ms / 30 帧均值 15.2ms）。

### 8.5 语音：更年轻的声音 + 提前生成 wav（2026-09-22 追加要求）

需求原文：「语音年轻点，速度慢点」，后追加「语音提前做好 wav 文件吧」。

**问题一：本机没有更年轻的语音。**
SAPI5 只有一个中文语音 `Microsoft Huihui Desktop`（成年女声、机械），
**这不是参数问题，是语音包的问题**。改用 edge-tts 的 `zh-CN-XiaoyiNeural`
（VoiceTag 场景=Cartoon、性格=Lively），中文语音列表里最年轻自然的一个。

**问题二：edge-tts 只出 mp3，而 mp3 必须走 MCI。**
MCI 的 `open`/`close` 是**阻塞调用**，且别名全局唯一 —— 新播会 `close` 掉
**正在播的那条**。这在频繁触发时表现为"有的语音没播出来"（实测踩过，见 §8.6）。

所以最终**提前生成 wav**：

| | wav（winsound 播） | mp3（只能 MCI 播） |
|---|---|---|
| 播放调用 | `PlaySound(SND_ASYNC)`，真异步、无设备开关开销 | `mciSendString` 阻塞调用 |
| 并发 | 天然安全 | 别名冲突，会掐断正在播的 |
| 体积 | ~100KB/条 | ~13KB/条 |

体积代价可接受（7 条不到 1MB）。**`Speaker` 的文件优先级改为 wav > mp3**，
MCI 只作 mp3 的兜底通道。

**转换怎么做的**：本机没有 ffmpeg，edge-tts 的 `outputFormat` 又硬编码在
私有嵌套函数里（改源码太脆）→ 用 **`soundfile`**（自带 libsndfile 1.2.2，
支持 mp3 解码）解码后写 wav。**不需要任何外部可执行文件。**

**语速与时长是取舍，不是两个独立旋钮**：
语速调慢会让片段变长，而报告 §7 要求 1~2 秒。所以"慢"用**压短文案**换：

| | 旧（Huihui） | 新（Xiaoyi） |
|---|---|---|
| 语速 | rate=+2（还加快过） | rate=-10%（放慢） |
| 单位语速 | 0.30 秒/字 | **0.44 秒/字（慢 47%）** |
| 文案 | 7 字 | **压到 4~5 字** |
| 实际时长 | 2.1 秒 | **2.0~2.2 秒** |

即：**单位语速明显变慢，但总时长没变长。**

旧 Huihui wav 归档在 `voice/sapi-huihui/`（不删，便于 A/B）。

### 8.6 提醒节奏与播放：实测踩出来的坑（2026-09-22 夜 / 09-23 修订）
用户报「有部分语音没播放成功，识别结果频繁出来，语音如果串行就来不及，卡住？」
—— **两个现象是同一个根因链**，都修了：

**① 提醒间隔原来只按问题分别计时（`last_fired` 用问题名做 key）**

后果：「头前倾」报过要等 90 秒，但「塌腰」是**独立计时**的，5 秒后就能再报。
孩子扭一下、问题名在 头前倾／塌腰／低头 之间轮换，就变成每 4~8 秒响一次。

修法：增加 `REMIND_GAP_ANY_SEC` —— **任意两次提醒之间**的全局下限，**跨问题也生效**。

需求原话（09-23）：「三十秒之内如果提示过不正确就不提示，即便不正确的原因也不一样。」
→ 该值定为 **30 秒**。两道闸并存：

| 参数 | 值 | 语义 |
|---|---|---|
| `REMIND_GAP_SEC` | 90s | 同一个问题两次提醒至少隔 90 秒 |
| `REMIND_GAP_ANY_SEC` | **30s** | 任意两次提醒至少隔 30 秒（跨问题） |

**② 坐正了不许发声**（需求：坐姿没问题就不要发出任何声音）

早期恢复正常时会 `chime("good")` 给个正反馈提示音 —— **已移除**。
正向激励改用界面表达（绿色大字 + 连续良好计时）。
唯一保留的提示音是**标定完成** `chime("done")`：那是系统事件、只响一次，
用来告诉家长基线采集好了，不是坐姿判定。

⚠️ 这条约束落在采集循环里，**没有摄像头就没法跑行为测试** →
用**源码级回归锁**代替（测试 H1/H3 断言不再出现该调用），改动时立刻失败。

**② 语音播放跑在推理线程里，而且是阻塞调用**

`_say_mci()` 第一步就 `close` 别名 —— 这会把**正在播的那条直接掐断**。
频繁触发时新的一条不断掐掉上一条，听感就是"有的没播出来"；而 MCI 的
`open`/`close` 是阻塞的，卡住的正是采集循环，对应"卡住"。

修法：`Speaker` 改成**独立播放线程 + 深度 1 的队列**。
- `say()` 只入队，**立即返回**（实测 0.18ms；旧实现几十~上百 ms）
- 队列满时**顶掉还没播的旧提醒** —— 提醒有时效性，积压一串过时语音比丢掉更糟
- 单线程串行播放，同一时刻只有一条在播，「掐断正在播的」问题自然消失
- 播放结果（含**失败原因**）通过 on_log 异步汇报 —— 原来出错时没有任何线索

### 8.7 阈值标定：改成「使用中顺手标注」，不再要求录视频

任务书 §6 原本的流程是「录 15~20 分钟视频 → 人工逐帧标注 → 扫阈值」。
**这条路不成立**：逐帧标注 15 分钟视频的成本太高，家长不会做，
而「误报率 < 10%」这个验收指标就永远算不出来。

改成在使用中收数据（`ReviewStore`）：

1. 每次**提醒时**自动存一张现场图（480px 缩略图 + 当时的指标与基线 + 问题名）
2. 另外按固定间隔（默认 180 秒）存一张「判为良好」的抽样
3. 家长在「家长设置 → 审核判定」逐条点「对／不对」
4. 该页底部用已审核样本**反推建议阈值**（`suggest_threshold`，误报权重 1.5×）

**三条必须说清的设计约束：**

| # | 约束 | 原因 |
|---|---|---|
| 1 | **只能发现误报，发现不了漏报** | 漏报时程序压根没存图 → 所以必须存「判为良好」的抽样，否则漏报率测不出来 |
| 2 | **一条样本只调它自己触发的那个指标** | 家长标「确实歪了」可能是因为塌腰，那一帧的 `neck_angle` 可能很低，拿它压 `neck_angle` 阈值是错的 |
| 3 | **方向要统一** | `neck_angle`/`trunk_angle` 是「比基线大才异常」，`head_collapse` 是「比基线小才异常」，不统一会扫反（`side_score()`） |

**这套数据只能调阈值，不能重训练模型**（用户 2026-09-22 已明确决定不做重训练）：

| | 调阈值 | 重训练模型 |
|---|---|---|
| 改什么 | 判定规则（12° → 16°） | 关键点模型本身 |
| 数据量 | 几十条 | 几百~几千张 |
| 标签 | 「对／不对」决策标签 | 每个关键点的 (x,y) 坐标 |
| 人工 | 每条 2 秒 | 每张 1~2 分钟 |

存的是 480px 缩略图且只有决策标签，**没有关键点真值，不能用于训练**。
`review_keep_fullres` 开关可另存原图为将来的 P3 微调铺路，**默认关闭**。

**隐私**（报告 §10 风险 8）：全部本机存储、不上传；上限默认 300 条，
超出自动删最旧且**优先删未审核的**（保证标注不丢）；页面内一键清空。
